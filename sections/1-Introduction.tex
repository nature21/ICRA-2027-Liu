\section{Introduction}

Recently, coding agents have shown remarkable capabilities in developing complex software systems, sparking growing interest in solving robotic manipulation tasks through programming~\cite{chen2026gap,xiao2026enpire,lu2026aspire,fu2026cap}. Consider how human engineers would develop a robot program to solve the task in Figure~\ref{fig:teaser} before the era of coding agents: given the \textit{(a) task specification} (pick up the cookie box), they would write a program that composes the available \textit{(b) manipulation primitives} (push the box to a fixture, flip it against the fixture, then grasp and lift it), and test the program in \textit{(c) interactive environments} to verify its correctness and iteratively debug it. This process mirrors the core strength of coding agents: not one-shot code generation, but the iterative cycle of generating, executing, verifying, and revising a program, commenly refered as the agentic coding loop~\cite{ng2026three,huang2023agentcoder}.

For the agentic coding loop to work in robotic manipulation, it requires three ingredients: task specification, manipulation primitives, and interactive environments for verification. Existing robotic coding-agent systems typically assume these ingredients are provided through human-engineered primitives, explicit task objectives, and resettable environments with reward or success feedback. This raises a fundamental question: \textbf{how can a coding agent close the loop when these ingredients are not provided a priori?}

We explore \textit{demonstrations} as a programming interface for supplying the task- and motion-level information needed by the agentic coding loop. A demonstration directly shows a feasible way to accomplish a task and, together with a laguage description, conveys the intended outcome. Importantly, rather than merely reproducing the demonstrated trajectory, we aim to use this information to recover an executable and reusable manipulation program. An additional challenge beyond getting the program is that demonstrations alone do not provide an interactive environment for iterative program verification and refinement, which is necessary for closing the agentic coding loop.

Motivated by this perspective, we introduce \textbf{R}obot \textbf{A}gentic \textbf{P}rogramm\textbf{i}ng from \textbf{D}emonstrations (\textbf{RAPID}), a framework for constructing and iteratively refining robot programs from a single human demonstration with a coding agent. Given a demonstration and a language description, RAPID infers the task specification, constructs the required manipulation primitives, and composes them into an executable manipulation strategy. It further reconstructs the demonstrated scene in simulation, creating an interactive environment in which the coding agent can execute the generated program, diagnose failures, revise the program, and repeat this process until the task specification is satisfied. To improve generalization, RAPID additionally generates sevaral scene variants to further verify and revise the program. In this way, RAPID automatically establishes the three ingredients required to close the agentic coding loop for robotic manipulation.

In this work, we apply RAPID to \textit{nonprehensile manipulation}, where the need for such a framework is especially acute. Many prehensile tasks can be composed from a compact and well-established set of reusable primitives, including \textit{pick}, \textit{move in free space}, and \textit{place}. Nonprehensile manipulation, by contrast, spans diverse and geometry-dependent contact interactions, including pushing, pivoting, toppling, flipping, and pressing \comment{?}. Capturing this diversity with a fixed primitive library is difficult: the required interaction modes can vary substantially across objects, scenes, and tasks, making manual primitive design itself a significant engineering burden. This makes nonprehensile manipulation a natural testbed for asking whether a coding agent can construct reusable manipulation primitives from a single demonstration rather than rely on human engineering.

A central challenge is \textit{generalization} beyond a single demonstrated scene. Programs that directly encode poses, distances, or waypoints may reproduce the demonstrated behavior but can fail when the scene changes. RAPID instead captures the manipulation in terms of object-centric relations and task-relevant effects. Specifically, RAPID represents primitives as relational trajectory-optimization programs that realize object-level motion effects, such as pushing an object by a displacement or flipping it by an angle. It specifies semantic object roles, their relations, and an effect parameter, while resolving scene-dependent geometry at execution time and optimizing a trajectory. At the task level, primitives are connected into a strategy through relational constraints that determine how the outcome of one phase specifies the next. For example, rather than replaying a fixed pushing distance, the program can compute how far an object should be pushed from its current pose to establish contact with a fixture. By expressing both individual interactions and their composition relationally, RAPID preserves the invariant structure of the demonstrated strategy while adapting to changes in object pose, size, geometry, and physical properties.


The remaining challenge is \textit{verification}: the coding agent needs an interactive environment in which candidate programs can be executed, evaluated, and revised. RAPID reconstructs such an environment in simulation from the demonstration and augments it with automatically generated scene variants. To expose scene-specific assumptions while avoiding invalid test cases, RAPID randomizes object geometry, pose, appearance, and physical properties, and uses agent-generated filters to retain only task-consistent and physically feasible variants. The coding agent then executes the program across these environments, evaluates it against inferred success predicates, and iteratively revises failures. This simulation-based verification closes the agentic loop and helps ensure that the resulting program generalizes beyond the demonstrated scene.


We evaluate RAPID on 8 contact-rich nonprehensile manipulation tasks, where the system receives a single demonstration and its language instruction and must construct a reusable manipulation strategy. Our primary evaluation focuses on \textit{generalization}: whether a program constructed from one demonstrated instance can succeed under substantial changes in object pose, geometry, physical properties, and scene configuration. We additionally evaluate the frozen programs on physical robots and conduct ablations to assess the contributions of the relational program representation, scene variation, and iterative verification.

Our contributions are threefold:

\begin{itemize}

\item We introduce RAPID, a framework that closes the agentic coding loop for robotic manipulation by automatically constructing \textit{(a) task specifications}, \textit{(b) manipulation primitives}, and \textit{(c) interactive verification environments}, all from a single human demonstration.

\item We introduce \textit{relational manipulation programs}, which represent manipulation primitives as parameterized trajectory-optimization programs and compose them through relational constraints, enabling reusable strategies that adapt across scenes.

\item We demonstrate that RAPID can construct reusable programs from a single human demonstration across diverse contact-rich nonprehensile manipulation tasks, generalize to substantial scene variations, and be deployed in the real world.

\end{itemize}
